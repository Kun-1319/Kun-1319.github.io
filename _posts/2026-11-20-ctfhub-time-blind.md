## 一、题目信息
- **平台**: CTFHub
- **题型**: Web，SQL注入
- **考点**: 时间盲注、sleep、if、采样与阈值判断

## 二、解题思路与踩坑记录

页面提交后只显示执行的SQL语句，既没有数据回显，也没有query_success这类文字。唯一能观察的只有响应时间。

先用两条请求量基线：

```
?id=1
?id=1 and sleep(2)
```

第一条0.37秒返回，第二条2.39秒。差值约2秒，说明sleep被执行了，时间通道成立。

思路：把判断条件塞进if里，条件成立就睡眠，不成立立刻返回。用响应时间区分真假，再按位把字符问出来。

**踩坑一：页面没有真假文字**

这题和布尔盲注不同，布尔盲注还有query_success和query_error两个词，这题连词都没有，只有SQL回显。所以判断依据只能是自己计时。

**踩坑二：网络抖动导致读错**

第一版阈值设0.85秒、睡眠1秒，结果库名读成`srli`，正确的是`sqli`；flag里还读出`>`这种不可能出现的字符。

原因是偶尔一次请求慢到0.9秒，被误判为“条件成立”，二分查找就往错误方向走，一个字错，后面全错。

解决办法有两条：每次判断采两次样、取最小值；同时把睡眠加到1.2秒、阈值提到0.9秒。取最小值能过滤掉偶发的慢请求，因为慢只会增加时间，不会减少。

**踩坑三：睡眠太短区分不开**

试过sleep(0.3)，基线本身就有0.2到0.4的波动，根本分不清。睡眠至少要比抖动幅度大一个数量级，本题用1.2秒够用。

## 三、解题步骤

1. **确认通道**:

```
?id=1 and sleep(2)
```

响应时间明显变长，说明可以控制时间。

2. **问长度**:

```
?id=1 and if(length((select database()))>3,sleep(1.2),0)
```

变慢说明条件成立；再问大于4，没变慢，得出长度4。

3. **逐位取库名**:

```
?id=1 and if(ascii(substr((select database()),1,1))>109,sleep(1.2),0)
```

二分逼近，得到`sqli`。

4. **取表名**:

```
?id=1 and if(ascii(substr((select group_concat(table_name) from information_schema.tables where table_schema=database()),1,1))>109,sleep(1.2),0)
```

结果`flag,news`。

5. **取字段名**:

表达式换成columns表，限定table_name为flag，得到`flag`。

6. **取flag**:

```
?id=1 and if(ascii(substr((select group_concat(flag) from flag),1,1))>109,sleep(1.2),0)
```

按位二分，长度32，结果`ctfhub{11090704c04b94525d741bf7}`。

7. **写成脚本**:

每个字符七次比较，每次采两次样取最小值。串行执行，不开并发，避免请求互相拖慢。

## 四、总结与反思

1. 时间盲注是最后的手段。没有回显、没有报错、连真假文字都没有时，只能靠时间。
2. 判断真假的关键是阈值。阈值要明显高于基线抖动，低于睡眠时长，留出安全区。
3. 采样策略决定准确率。单次采样容易被网络抖动污染，取最小值能把“偶发变慢”过滤掉。
4. 一个字错，后面全错。所以每读一段，最好回到已知结果上校验，比如先读库名，和之前题目对比。

## 五、问题与解答

**问：时间盲注的原理。**

答：让数据库在条件成立时执行sleep，响应时间变长；条件不成立时不睡眠，立刻返回。用时间差代替页面回显，得到一位真假信息。

**问：为什么用if而不直接and sleep。**

答：`and sleep(1)`只要语句执行到就会睡，和条件无关，没法区分真假。`if(条件,sleep(1),0)`把睡眠挂在条件上，条件不成立就不睡。

**问：为什么取两次的最小值。**

答：网络只会让请求变慢，不会让它变快。两次取最小值，等于排除了偶发的慢响应，减少误判。

**问：睡眠设多长合适。**

答：比基线抖动大一个数量级。基线0.2到0.4秒，睡眠设1.2秒，阈值设0.9秒，三者的关系是安全区。

**问：为什么不能开并发。**

答：并发会让多个请求同时占带宽，响应时间互相污染，判断依据就不准了。时间盲注必须串行。
