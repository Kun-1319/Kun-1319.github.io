## 二、库、表、字段的关系

MySQL的数据是四层结构：

```
MySQL服务器
└── 库（database，也叫schema）
    └── 表（table）
        ├── 字段（column，列）
        └── 记录（row，行）
```

以dvwa库的users表为例：

| user_id | user | password |
|---|---|---|
| 1 | admin | 5f4dcc3b5a |
| 2 | gordonb | e99a18c428 |

user_id、user、password是三个字段，每一行是一条记录，单元格里是值。

schema和database在MySQL里是同一个东西，`show databases;`和`show schemas;`结果一样。Oracle和PostgreSQL把两者分开，MySQL没有分。

## 三、特殊库有哪些

特殊库指MySQL安装时自带的系统库，存的不是业务数据，而是数据库自己的信息。

| 库 | 作用 | 可读可写 |
|---|---|---|
| information_schema | 元数据：所有库、表、字段 | 只读 |
| mysql | 账号、权限、存储过程 | 可写 |
| performance_schema | 性能监控：语句耗时、锁等待 | 只读 |
| sys | 基于performance_schema的视图，更好读 | 只读 |

information_schema里最常用的三张表：

| 表 | 存什么 | 关键字段 |
|---|---|---|
| schemata | 所有库 | schema_name |
| tables | 所有表 | table_schema、table_name |
| columns | 所有字段 | table_schema、table_name、column_name |

## 四、常用操作

进入MySQL后依次执行：

```sql
show databases;
use dvwa;
show tables;
desc users;
```

结果：`show databases;`列出33个库，dvwa在其中；`show tables;`返回guestbook和users两张表。

不切换库也能查表名：

```sql
select table_name from information_schema.tables where table_schema='dvwa';
```

返回同样的两张表。这条和`use dvwa; show tables;`等价，区别是它可以在任意库下执行，不需要先切换。

查字段：

```sql
select column_name from information_schema.columns where table_schema='dvwa' and table_name='users';
```

查账号：

```sql
use mysql;
select user, host from user;
```

## 五、踩坑记录

**坑一：select少了from**

写`select * information_schema.columns;`，报ERROR 1064。SQL要按select、from、where三部分写，from不能省。

**坑二：提示符变成->时又敲新语句**

第一条语句没写分号，提示符变成`->`，表示还在等这条写完。这时输入新语句会被接到后面，拼成一条乱七八糟的语句，继续报1064。

正确做法：输入`\c`回车取消，回到`mysql>`重新写。注意是反斜杠，输成`/c`不生效。

**坑三：把命令当函数写**

写`show databases();`，报1064。show是命令，后面直接跟名词加分号；database()是函数，只能放在select里用。

正确写法：

```sql
show databases;
select database();
```

**坑四：库名记错**

以为有个库叫information_databases，实际叫information_schema。名字由information和schema组成，意思是“关于库的信息”。

**坑五：dvwa不在库列表里**

`show databases;`里没有dvwa，原因是DVWA不会自动建库。需要浏览器打开DVWA，登录后点Create / Reset Database，数据库才被创建。没初始化之前，MySQL里当然看不到。

**坑六：SSH连不上**

Windows新版SSH客户端默认禁用ssh-rsa算法，连接老系统时协商失败，报`no matching host key type found`。加上参数即可：

```
ssh -o HostKeyAlgorithms=+ssh-rsa root@192.168.216.129
```

## 六、问题与解答

**问：select后面什么时候用*。**

答：探索表结构、不知道有哪些列时用；只关心几列、表很大、注入拼UNION时不要用。UNION要求列数明确，写*无法对齐。

**问：字段是什么意思。**

答：字段就是列，是表头。一行记录在每个字段上各有一个值。

**问：为什么注入不能直接use库再show tables。**

答：注入点只能执行一条SELECT，没法先切换库。所以只能靠information_schema加where条件，一条查询把表名取出来。

**问：既然能直接读dvwa，为什么还要查information_schema。**

答：有客户端权限时确实可以直接读。但注入时你不知道库名、表名、字段名，只有一个参数入口，information_schema是唯一能问出结构的地方。

**问：UNION的要点是什么。**

答：两条查询列数必须一致，类型要兼容；结果集的列名取自第一条查询；数字和NULL可以当占位符，NULL兼容性最好。

**问：show databases和查tables表的区别。**

答：show databases列出所有库，空库也算；查tables表只列出有表的库，空库不会出现。

## 七、总结与反思

1、库、表、字段、记录是四个层级，理解了这四层，后面所有SQL操作都是在其中定位。
2、information_schema是数据库自带的地图，注入时先查地图再取数据，顺序不能颠倒。
3、报错信息要读懂。1064是语法错，看near后面的内容就知道断在哪；1049是库不存在；1146是表不存在。
4、命令和函数要分清。show、use、desc是命令，database()、version()、user()是函数。
5、环境问题也是学习内容。SSH算法协商、控制台字体限制、DVWA初始化，这些不在课程里，但每个都会卡住人。
