## 题目信息

题目：SVN 泄露  
平台：CTFHub  
环境：Kali Linux  
工具：dvcs-ripper、Perl

## 解题思路

SVN，也就是 Subversion，是一种版本控制工具。开发人员使用它管理代码时，本地工作副本中会有一个 .svn 目录，用来保存管理信息和文件内容的原始副本。

如果部署网站时，把 .svn 目录一起放到了网站目录下，又没有禁止外部访问，就可能造成源码泄露。

这道题的思路是：使用 dvcs-ripper 下载暴露的 .svn 数据，再检查其中保存的文件内容，寻找 flag。

需要注意，.svn 是工作副本的管理目录，不是保存完整历史的服务端仓库。能否找回旧内容，取决于实际泄露的数据。本题中保留了包含 flag 的文件副本。

## 解题步骤

### 1. 进入工具目录

我已经把 dvcs-ripper 解压到了 Kali 桌面，进入工具目录并打开终端：

```bash
cd /home/kali/Desktop/dvcs-ripper-master
```

这个目录中有多个脚本，分别用于处理不同版本控制工具的数据。本题是 SVN 泄露，所以使用 rip-svn.pl。

.pl 是 Perl 脚本的扩展名，因此可以通过 Perl 解释器运行：

```bash
perl rip-svn.pl
```

不过，只输入这一条命令并没有提供目标网址，所以不能据此判断靶场是否存在 SVN 泄露。运行时还需要通过 -u 指定地址。

### 2. 指定靶场的 .svn 地址

执行：

```bash
perl rip-svn.pl -u http://challenge-21271036a5556c58.sandbox.ctfhub.com:10800/.svn/
```

这里各部分的作用是：

- perl：使用 Perl 解释器运行脚本。
- rip-svn.pl：处理 SVN 工作副本数据的脚本。
- -u：指定需要读取的目标 URL。
- /.svn/：网站可能暴露的 SVN 管理目录。

第一次运行时，脚本识别到了新的 SVN 工作副本存储格式，但随后报错：

```text
install_driver(SQLite) failed
Can't locate DBD/SQLite.pm in @INC
```

这说明当前遇到的问题是本地 Perl 环境缺少 SQLite 驱动，而不是已经证明靶场无法读取。

较新的 SVN 工作副本使用 SQLite 数据库存储管理信息，脚本需要相应的 Perl 模块才能解析。

### 3. 安装缺少的依赖

安装 SQLite 对应的 Perl 驱动：

```bash
sudo apt install -y libdbd-sqlite3-perl
```

其中，sudo 用于取得安装软件所需的权限，apt install 用于安装软件包，-y 用于自动确认安装提示。

安装过程中出现了系统库和服务重启相关的配置界面，完成配置并等待安装结束即可。

这里安装依赖只是为了让脚本正常运行，并不是直接获取 flag。

### 4. 再次运行脚本

依赖安装完成后，重新执行：

```bash
perl rip-svn.pl -u http://challenge-21271036a5556c58.sandbox.ctfhub.com:10800/.svn/
```

这次输出中出现：

```text
Found new SVN client storage format
```

随后出现：

```text
Reverted index.html
```

说明工具已经下载了部分 SVN 数据，并利用这些数据恢复出了 index.html。

这里恢复的是 Kali 本地的文件，不是修改远程靶场。恢复出首页也不代表已经找到 flag，还需要检查下载的数据。

### 5. 查看本地 .svn 目录

执行：

```bash
ls -al .svn
```

可以看到：

```text
entries
format
pristine
text-base
tmp
wc.db
wc.db-journal
```

其中，wc.db 是 SQLite 数据库，用来记录工作副本的管理信息；pristine 保存文件内容的原始副本。

隐藏目录并不等于加密目录。.svn 前面的点只是让它在普通目录列表中默认隐藏，不能阻止网站服务器把里面的文件提供给外部访问。

### 6. 查找文件内容副本

继续执行：

```bash
find .svn/pristine -type f
```

find 用于查找文件，.svn/pristine 是查找范围，-type f 表示只列出普通文件。

本次找到了两个以 .svn-base 结尾的文件。它们的文件名是一长串哈希值，因此不能直接通过名字判断里面是什么内容。

这些哈希主要用于标识和校验内容，不代表文件经过了加密。接下来可以直接读取文件。

### 7. 读取内容并找到 flag

执行：

```bash
cat .svn/pristine/*/*.svn-base
```

这条命令会读取 pristine 下一层子目录中的 .svn-base 文件。

第一个 * 匹配子目录，第二个 * 匹配文件名，cat 则把匹配文件的内容依次输出到终端。

输出中出现了完整的 ctfhub{...} 字符串，后面还有一段 HTML：

```html
<html>
<head>
    <meta charset="UTF-8" />
    <title>CTFHub 信息泄露 SVN</title>
</head>
<body>
    <h1>题目 - Subversion</h1>
    <br>
    <p>Flag 在服务端旧版本的源代码中</p>
</body>
</html>
```

这里的 flag 和 HTML 来自命令匹配到的不同文件。由于 cat 会连续输出文件内容，如果前一个文件末尾没有换行，就会显示成 flag 后面紧接着 HTML。

提交时只需要复制完整的 ctfhub{...} 字符串，不要把后面的 HTML 一起复制进去。本次已经从文件副本中找到 flag。

## 笔记

这道题的关键是理解：浏览器当前看到的网页，并不代表服务器上只有这一份内容。部署时遗留的版本控制数据，也可能保存源码副本。

本次操作可以分成三个阶段：

1. 使用 rip-svn.pl 下载靶场暴露的 SVN 数据。
2. 安装缺少的 SQLite 驱动，让工具能够解析管理信息。
3. 在本地检查 pristine 中的文件副本，找到 flag。

工具显示恢复了 index.html，只能说明恢复出一个文件，不能直接说明 flag 就在这个文件里。继续查看实际下载的数据，才找到了本题需要的内容。

防护时，应当从部署产物中排除 .svn 等版本控制目录，同时在 Web 服务器中禁止访问这些目录。仅仅让目录隐藏，不能防止通过 HTTP 读取其中的文件。
