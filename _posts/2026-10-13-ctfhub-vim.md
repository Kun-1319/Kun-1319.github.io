## 题目信息

- **平台**：CTFHub
- **题目**：vim缓存
- **考点**：Vim 交换文件泄露

题目提示，开发者在线上使用 Vim 编辑文件时，会产生缓存文件。如果 Vim 异常退出，这些文件可能留在服务器上，导致网站源码泄露。

## 解题思路

Vim 是一种文本编辑器，可以用来修改文字和代码。编辑文件时，它通常会生成交换文件，保存一些用于恢复编辑内容的数据。这样即使程序突然退出，也有机会找回没有保存的内容。

比如用 Vim 编辑 `index.php`，通常会生成：

```
text.index.php.swp
```

这个文件名最前面有一个点，最后的 `.swp` 是交换文件的后缀。

根据题目提示，我尝试访问这个文件。如果它留在网站目录下，而且服务器允许下载，就可能从里面找到源码或 flag。

## 解题步骤

### 1. 尝试访问交换文件

开启题目环境后，我先在网址后面添加了：

```text
/index.php.swp
```

页面返回了 `404 Not Found`，表示服务器没有找到这个路径。

检查文件名后，发现少了最前面的点。Vim 生成的交换文件通常叫 `.index.php.swp`，这个点也是文件名的一部分，不能省略。

于是把网址末尾改成：
```text
/.index.php.swp
```
完整地址的格式如下：
```
text
http://题目域名:端口/.index.php.swp
```域名和端口使用题目环境提供的实际地址。

### 2. 下载并查看文件

修改路径后，成功下载到了交换文件。

我用记事本打开文件，查看里面的内容。交换文件不是普通的文本文件，里面可能夹杂乱码，但这次仍然能在记事本中找到 flag。

### 3. 找到 flag

在文件内容中找到 flag 后，就得到了本题需要的答案。

这次直接查看下载文件就找到了 flag，没有使用 Vim 恢复源码。

## 笔记

这道题最容易漏掉的是文件名前面的点。`index.php.swp` 和 `.index.php.swp` 是两个不同的文件名，服务器会按照输入的路径寻找文件，不会自动帮我们补上这个点。

`.swp` 来自英文 swap，表示交换文件。它和上一题的 `.bak` 都可能泄露信息，但产生的原因不一样：`.bak` 通常是备份文件，`.swp` 则是 Vim 在编辑过程中生成的临时文件，用来帮助恢复内容。

这次用记事本就找到了 flag，但不能因此认为所有 `.swp` 文件都可以直接读懂。如果里面的内容不完整，或者被内部数据打乱，就可能需要使用 Vim 的恢复功能进一步查看。

网站安全也需要注意这些临时文件。即使原来的 PHP 文件只能看到运行结果，遗留下来的交换文件仍然可能暴露源码。因此，除了保护正常的网站文件，也要检查有没有不该公开的备份和临时文件。
